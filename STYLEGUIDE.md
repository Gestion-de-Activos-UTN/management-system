# SIAM Frontend — Style & Conventions Quick Reference

Full rationale: `documentation/09-frontend-architecture.md`. Hard rules: `SYSTEM_PROMPT.md`. This file is the fast lookup during day-to-day work — if it conflicts with either, they win.

## Palette

Two custom Mantine color scales, defined in [lib/theme.ts](lib/theme.ts):

| Scale | Role | Base shade |
|---|---|---|
| `bone` | Neutral — backgrounds, borders, dimmed text. Warm off-white instead of cool gray. | `bone.0` (#faf8f4) page bg, `bone.9` near-black text |
| `pine` | Primary accent — muted slate-teal. Buttons, links, active nav, focus rings. | `pine.6` (#3d7266) light mode, `pine.4` dark mode |

Semantic status colors (`red`/`yellow`/`green`) stay Mantine defaults — criticality/online-offline badges need universal at-a-glance meaning, not brand novelty. Never invent a new semantic color for status; use [components/ui/StatusBadge.tsx](components/ui/StatusBadge.tsx) tones (`success` `warning` `danger` `info` `neutral`).

Don't hardcode hex values in components — reference theme colors (`c="pine.6"`, `bg="bone.0"`) so a future palette swap is one file.

## Folder layout (committed, per doc09 §9.1)

```
app/(dashboard)/          route pages, thin — layout/data wiring only
app/(payload)/            Payload's autogenerated admin, untouched
app/portal/               non-admin end-user views
modules/<domain>/         one per business domain (assets, organizations...)
  components/             domain-specific presentation
  hooks/                   use-*.ts, only place that calls TanStack Query
  service.ts               only place that calls http-client for this domain
  schema.ts                extends contracts/ for UI-only form rules
  store.ts                 Zustand, only if UI state outlives a component
contracts/                 Zod schemas shared with scanner-prototype
components/ui/             generic, zero domain knowledge (DataTable, StatusBadge)
components/layout/         app shell (Sidebar, TopBar, DashboardShell)
lib/                       theme.ts, providers.tsx, query-client.ts, http-client.ts
```

`modules/` and `contracts/` are created as each domain ships — don't scaffold empty domain folders speculatively.

## Non-negotiables (see SYSTEM_PROMPT.md for the "why")

- Mantine only — no Chakra/MUI/AntD/raw unstyled HTML where a Mantine primitive exists.
- Lucide only for icons, imported by name.
- Never call `useReactTable` outside [components/ui/DataTable.tsx](components/ui/DataTable.tsx) — extend it instead.
- Never call `useQuery`/`useMutation` in a presentation component — only in `modules/<domain>/hooks/`.
- Never `fetch` directly — through `lib/http-client.ts` (not yet built — add when the first module needs real data).
- Never compute RBAC in a component (`role === 'OrgAdmin'`) — permissions arrive resolved from `TenantContext`.

## Naming

Components `PascalCase.tsx`, hooks `use-*.ts` exporting `camelCase`, services `<module>.service.ts`, stores `<module>.store.ts`, table columns `<module>.columns.tsx`, everything else `kebab-case`.
